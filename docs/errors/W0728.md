# W0728

**A `theme/strings*.json` key is not one the theme shows, or the file could not be read**

| | |
|---|---|
| Severity | Warning |
| Area | Build, cache, assets, determinism |
| Raised by | `liyasa-build` |

A key in `theme/strings.json` or `theme/strings.<locale>.json` is not one of the
words the theme shows, or the file could not be read at all. The key is ignored
and the theme keeps its own wording, which is why this is worth saying: a typo
here used to change nothing and report nothing.

## Fix it

Correct the key. The warning names the file and suggests the declared key it is
closest to:

```json
{
  "onThisPage": "In dieser Datei",
  "searchPlaceholder": "Dokumentation durchsuchen"
}
```

Every key is listed under `docs/reference/` and in
`liyasa_theme::strings::Strings::KEYS`. A file is one flat object of strings; a
nested object or a number is not a wording and is reported the same way.

The files layer, least specific first: `theme/strings.json`, then the language's
file, then the locale's. For `pt-BR` that is `theme/strings.json`,
`theme/strings.pt.json`, `theme/strings.pt-BR.json`, so a site-wide rebrand and
one translated word can coexist without either restating the other.

A file that will not parse costs only the words it names — the layers under it
stay in place — so a broken override never takes a published site down.

Related: [`E0101`](E0101) for `liyasa.json` itself failing to parse.
