# W0019

**A verification check class could not run in this build**

| | |
|---|---|
| Severity | Warning |
| Area | CLI and I/O |
| Raised by | `liyasa-cli` |

A class of verification check did not run in this build. The message names the
class and why.

| Class | What it needs |
|---|---|
| `code` | `liyasa verify` to call the verification orchestrator, and a container sandbox |
| `facts` | `liyasa verify` to call the verification orchestrator |
| `screenshots` | A screenshot check, which is not built, and the companion runtime to capture a page |
| `prose` | `liyasa verify` to walk each page's syntax tree |

The orchestrator and the sandboxed runners are both in `liyasa-verify`. What is
missing is this command calling them, so installing a container runtime does not
by itself make `code` run.

## What to do

Read it before trusting a green verification run. "No findings" means something
quite different when a whole class was skipped, and this warning is the only
thing that distinguishes the two.

Nothing you install on this machine makes `code`, `facts` or `prose` run today:
they wait on the CLI, not on your setup. A container runtime
([`E0004`](/errors/E0004)) and the companion ([`E0003`](/errors/E0003)) are
still what `code` and `screenshots` will need once the CLI drives them. See
[sandbox setup](/help/sandbox) and [verification](/guides/verification).

In CI, treat this as a failure rather than a warning if the class is one you
depend on. A check you believe is running and is not is worse than one you know
is absent.
