# W0139

**A configured operator holds their role whatever the membership table says, and removing them from the organization does not revoke it**

| | |
|---|---|
| Severity | Warning |
| Area | Configuration |
| Raised by | `liyasa-config` |

`auth.operators` names at least one subject, and a role granted there cannot be
taken away by the organization. Role sources are asked in order and the first
answer wins, so removing somebody from the organization — the obvious correct
thing to do when they leave — leaves them holding whatever this list gives them.

The warning names the subjects rather than counting them, so that somebody
reading a build log can tell whether the person who just left is one of them.

## Fix it

An operator entry is a break-glass key: it exists so that a fresh instance,
whose membership table is empty and therefore elevates nobody, has somebody who
can add the first member. Once that member exists, delete the entry:

```json
{ "auth": { "mode": "oidc", "operators": [] } }
```

Until then the warning is correct and there is nothing to fix — it is the
standing grant made visible rather than remembered. If an operator has left,
removing their membership row is not enough; remove them here too.

See [W0137](/errors/W0137) for an operator entry no sign-in can ever match.
