# W0729

**A page's region gate admits no region, so no reader reaches it and it is left out of search**

| | |
|---|---|
| Severity | Warning |
| Area | Build, cache, assets, determinism |
| Raised by | `liyasa-build` |

A page's `regions` gate resolves to no region at all, so no reader can be served
it: `only` and `except` name the same region, or `except` removes every region
the site declares. The page is still built and still routed — it is simply
absent from search, because a search result nobody may open is worse than no
result.

## Fix it

Look at the two lists together. The usual cause is one region named twice:

```yaml
---
title: Pricing
regions:
  only: [us]
  except: [us]   # remove this line
---
```

`only` and `except` compose rather than override: `only` chooses the set and
`except` narrows it, so naming a region in both removes it. An `except` that
lists every entry of `regions.list` has the same effect and is easier to reach
as the list grows — prefer `only` with the regions you want when the exclusion
would cover most of them.

If the page genuinely should reach nobody, `draft: true` says so where a reader
of the front matter will understand it, and `hidden: true` keeps it routable but
out of every index.

Related: [`W0725`](W0725) for a gate naming a region `regions.list` does not
declare, which is the other way a gate can admit less than its author meant.
