# E0808

**Webhook signature, timestamp, or delivery ID rejected**

| | |
|---|---|
| Severity | Error |
| Area | Server, auth, deployments, network |
| Raised by | `liyasa-server` |

A webhook delivery arrived that Liyasa could not prove came from your git host,
so nothing was built.

The three checks are separate, and the message says which one refused: the
HMAC-SHA256 signature over the raw body did not match the configured secret;
the delivery's timestamp was more than five minutes from now, where the
provider sends one; or the delivery ID had already been accepted in the last
twenty-four hours, which is a replay.

## Fix it

A signature failure is almost always the secret. The secret configured in
Liyasa and the one in the provider's webhook settings must be byte-identical —
a trailing newline from a copy and paste is enough to break it.

If your webhook goes through a proxy that rewrites or re-encodes the body, the
signature cannot survive it: the provider signs the bytes it sent, and Liyasa
verifies the bytes that arrived. Configure the proxy to pass the body through
untouched.

A stale timestamp on a delivery that is otherwise fine means the two clocks
disagree. Check NTP on the Liyasa host.

A replay usually means a provider retrying a delivery Liyasa already accepted
but answered slowly. Nothing is wrong; the second delivery is correctly
ignored.

See [E0806](/docs/errors/E0806) for outbound requests the network policy
refused.
