# E0910

**AI provider is unknown, unconfigured, or cannot serve the requested role**

| | |
|---|---|
| Severity | Error |
| Area | AI, agent, automations |
| Raised by | `liyasa-ai` |

`ai.models.<role>` names a provider this build cannot reach, or one that does not offer the role it was routed to.

## Fix it

Check the provider half of the `provider:model` string. The names this build knows are `anthropic`, `openai`, `google` and `ollama`; anything else is treated as an OpenAI-compatible endpoint and needs its address:

```json
{ "ai": { "models": { "assistant": "groq:llama-3.3-70b" },
          "providers": { "groq": { "baseUrl": "https://api.groq.com/openai/v1" } } } }
```

Some providers cannot serve some roles. Anthropic has no embedding endpoint, so `ai.models.embeddings` must point elsewhere. Amazon Bedrock signs every request with SigV4 and no signing crate is in the dependency table, so it is refused where it is configured rather than at the first call.

A key is never part of this setting: it comes from the environment or the server's secret store.

Related: [E0901](/errors/E0901) when the provider is reachable and answers with an error, [E0902](/errors/E0902) when the run exhausts its budget.
