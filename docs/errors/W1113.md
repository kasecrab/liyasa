# W1113

**Source configuration key has no Liyasa equivalent and was not carried**

| | |
|---|---|
| Severity | Warning |
| Area | Importers |
| Raised by | `liyasa-import` |

A key in the source project's configuration has no Liyasa equivalent, so it was
not carried across. One key at a time, not one section.

The conversion is an allow list rather than a copy. The configuration schema
sets `additionalProperties: false`, so a key carried across on hope would fail
validation at the end of a migration instead of being reported during it. The
leftovers are computed by difference, which means a key the source tool adds
next year is reported rather than silently dropped.

## Fix it

Read the named key in the migration report and set the nearest Liyasa option by
hand, or accept the default. Each key stands alone; nothing else in the
configuration is affected.

Keys that commonly reach this from Mintlify: `contextual`, `styling`,
`api.playground`, a `colors.*` entry outside `primary`, `light`, `dark` and
`background`, an `icons.library` outside the four the schema allows, and the
`theme` preset name. [The configuration reference](/reference/config) is
generated from the schema and is the list of what does exist.
