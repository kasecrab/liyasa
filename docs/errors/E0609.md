# E0609

**`verify` fence attribute is not a value Liyasa can read**

| | |
|---|---|
| Severity | Error |
| Area | Verification and facts |
| Raised by | `liyasa-verify` |

A fence asked to be verified and one of its `verify` attributes carries a value
Liyasa cannot read — an `exit` that is not a whole number, a `timeout` that is
not a duration, an `env` item with no `=`, or a `verify=` value that is neither
`compile` nor `skip`.

## Fix it

Correct the attribute on the fence. The spellings are `exit=1`,
`timeout=90s` (a whole number then `ms`, `s`, `m`, `h`, or `d`),
`env="KEY=value"` or `env="A=1, B=2"`, and `verify`, `verify=compile`, or
`verify=skip`:

````markdown
```bash verify timeout=90s exit=0 expect="Built 12 pages"
liyasa build
```
````

The attribute Liyasa could not read is ignored and the rest of the block still
runs, so a single typo never silently turns a verified block into an unverified
one.

Related: [E0635](E0635.md) is the same reading applied to the `verify` object in
`liyasa.json`; [E0602](E0602.md) is a block whose language has no runner at all.
