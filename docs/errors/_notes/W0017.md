An `openapi` source points at a URL, and this build has no HTTP client, so the
spec was not fetched or checked.

Nothing failed. The point of the warning is that a validation run which skipped
a spec entirely must not read as a validation run that passed.

## Fix it

Vendor the spec into the project and point at the file:

```json
{ "openapi": [{ "id": "api", "source": "openapi/api.yaml" }] }
```

That is worth doing regardless of this warning. A build that fetches its API
description at build time produces a different site depending on when it ran,
which is the opposite of what a lock file and a reproducible build are for.
