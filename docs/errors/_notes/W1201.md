The files this page needs to expand came to more than 2 MB, so the browser
module declined to render it and the editor asked the preview endpoint instead.

The editor seeds its file system with the open page and everything that page's
dependency record names — its snippets, components, vars and facts — in one
request when the page opens. The whole content tree is never shipped to the
browser. Past 2 MB the preview stops being the fast local render it exists to
be, so it moves to the server, where the same pipeline produces the same HTML.

## Fix it

Nothing is broken and the page still previews; it previews a little slower. To
bring it back into the browser, look at what the page includes:

```sh
liyasa build --json | jq '.pages[] | select(.route == "/your/page") | .includes'
```

A page that pulls in a large shared snippet on every render is usually the
cause; splitting the snippet so the page includes only the part it uses brings
the preload set back under the cap.
