The model provider was reached and answered with a failure, or the call to it did not complete.

## Fix it

The message carries the provider's own status and text. For `401` or `403`, the key is missing or wrong: it comes from the environment or the server's secret store, never from `liyasa.json`, and `ai.providers` holds only non-secret settings such as `baseUrl`. For `429`, the provider is rate-limiting; the re-index job backs off on its own, a reader request does not.

A `blocked by network policy` message is not the provider refusing but Liyasa refusing: every model call goes out under `Purpose::ModelProvider` and the address rules of the outbound policy apply. A self-hosted endpoint on a private address — Ollama on `localhost`, a vLLM server on the intranet — needs `network.allowPrivate`.

Related: [E0910](/errors/E0910) when the provider is not reachable at all, [E0902](/errors/E0902) for a budget.
