A `contextRepos[]` entry breaks one of the rules a clone is planned by, so that
repository is never read: it lists no paths, a path climbs out of the repository
with `..`, or the project configures more than ten entries. The message names
which one.

Nothing fails at build time — the clone happens when a deploy runs, on the build
worker, which is a long way from the file that got it wrong. This warning is the
same refusal, where it can still be edited.

## Fix it

For an entry with no paths, name what Liyasa may read. Empty is not
"everything"; it is nothing:

```json
"contextRepos": [
  { "repo": "acme/api", "paths": ["openapi.yaml", "spec/"], "depth": 1 }
]
```

A path is relative to the root of the repository it names, so `spec/openapi.yaml`
is right and `../spec` reaches outside it. A leading slash is not an escape:
`/spec` means that repository's own `spec`, which is how git's sparse-checkout
spells an anchored path.

Over the limit, combine entries that name one repository, or drop the ones this
project does not read.

See [W0134](/errors/W0134) for a section an untrusted build may not run, and
[E0002](/errors/E0002) for a file Liyasa could not read.
