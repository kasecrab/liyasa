`regions.detection` includes `header`, so the build expects a region to arrive in
`CF-IPCountry`, `X-Vercel-IP-Country`, `X-Liyasa-Region` or the header named by
`regions.header` — and `server.trustedProxies` is empty, so the server ignores
every one of them and that detection step never fires. Readers fall through to
the next source in the list, or to `regions.default`.

## Fix it

Name the peer that sets the header:

```json
{
  "server": { "trustedProxies": ["173.245.48.0/20"] },
  "regions": { "detection": ["header"], "header": "CF-IPCountry" }
}
```

The CIDR is your edge — the CDN, load balancer or reverse proxy that terminates
the connection and writes the header. It is not the reader's address.

The check exists because the header is the one thing in the request a reader can
write themselves. A client talking to the origin directly can send
`CF-IPCountry: us` as easily as Cloudflare can, and the region decides which
content exists for them, so a header from an unlisted peer is discarded rather
than believed.

If regions are decided some other way, drop `header` from `regions.detection`
and the warning goes with it:

```json
{ "regions": { "detection": ["auth", "choice"] } }
```
