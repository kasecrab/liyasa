Something named a region that `regions.list` does not contain — a page's
`regions` front matter, a navigation node, a `:::region` block, or a cell of the
availability matrix. The gate is not ignored: a region the site does not declare
matches no reader, so the page, node or block is withheld from everyone.

## Fix it

Either declare the region:

```json
{ "regions": { "enabled": true, "list": ["us", "ca", "eu"], "default": "us" } }
```

or correct the name where it was used. The warning names the file or route that
used it, and suggests the declared code it is one edit away from:

```md
---
regions:
  only: [us, ca]
---
```

Codes are matched exactly, so `US` and `us` are one region only if that is how
`regions.list` spells it — the build accepts either case from a request header
and normalizes to the declared spelling, but a gate written in content has to
match. Aggregates such as `eu` are ordinary entries in `regions.list`; there is
no built-in set.

Related: [`W0724`](W0724) for region detection that is configured and cannot
fire.
