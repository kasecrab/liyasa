The key exists in the schema but its value has the wrong shape. The message
carries the path, what was expected, and what was found.

## Fix it

[The configuration reference](/reference/config) gives the type of every key.
The common causes are a string where a list is expected, and an object where
the shorthand form was meant:

```json
{ "redirects": [{ "source": "/old", "destination": "/new" }] }
```

is accepted as shorthand for `redirects.rules`, but a bare string is not.

[`E0110`](/errors/E0110) is the neighbouring case: the key is not in the schema
at all.
