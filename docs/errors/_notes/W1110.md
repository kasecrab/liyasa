A tag or directive names a component that is neither built in nor defined by the
project. Both spellings are checked, so `<CodeGroup>` resolves through
`code-group` and only a genuinely unknown name reaches this.

It is nearly always a React component from the source project's own
`src/components/` or `snippets/components/`.

## Fix it

The importer writes a stub at `components/<name>.jinja` declaring every prop the
pages used it with, and leaves the tag where the author put it, so the converted
page builds and renders. Write the markup in that stub once.

:::tip{title="Counted once per project, not once per page"}
A component used on 29 pages is one file to write, not 29 pages to fix, so the
migration report names it once with a count and those 29 pages still score as
clean. Do not read the count as a page backlog.
:::
