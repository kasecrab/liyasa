This code is retired and nothing raises it. A key that is not in the
configuration schema is reported as [`E0103`](/errors/E0103), which says the
same thing and is what every release has actually emitted.

The code keeps its row in the registry so that a suppression list, a `--deny`
flag, or a CI filter that names it still parses. It matched nothing before and
it matches nothing now.

## Fix it

Nothing to fix here. If you arrived from a diagnostic, it was
[`E0103`](/errors/E0103); if you filter on `E0110`, move the filter to `E0103`
to catch what you meant to catch.

`plan/rfcs/0108-e0110-is-e0103.md` records why one of the two rows went and why
it went this way rather than by deleting the row.
