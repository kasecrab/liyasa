The custom domain did not prove that it points at this server, so it was not
added.

Verification fetches a token from the domain over HTTP and compares it to the
one issued when the domain was added. The message says which step failed: the
host did not answer at all, it answered with a status other than 200, it served
a different token, or the token had expired.

## Fix it

A host that does not answer has not been pointed here yet. Create the CNAME or
A record first — verification proves the name resolves to this server, not only
that you own it, so the record has to exist before it can pass.

A different token means the name resolves somewhere else: another Liyasa
instance, a parked page, or a CDN that has not picked up the new record.
Resolve the name and check where it lands before verifying again.

A token expires a week after the domain is added. Add the domain again for a
fresh one; nothing else is lost.

Verification never follows a redirect. A host that redirects to `https://` or
to `www.` cannot be verified, because whoever controls the redirect target is
not necessarily whoever owns this name — point the record directly.

See [E0802](/docs/errors/E0802) for certificate issuance, which runs after a
domain is verified.
