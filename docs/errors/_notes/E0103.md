The config names a key the schema does not have. Usually a typo, a key from
another documentation tool, or a key from a newer Liyasa than the one running.

The key is reported and then dropped, so the rest of the config still loads and
the build still runs. Nothing silently takes effect: an unknown key never
configures anything.

## Fix it

Check the spelling against the generated
[configuration reference](/reference/config), which is built from
`schemas/liyasa.schema.json`. `liyasa schema config` prints the same schema, so
an editor pointed at it autocompletes and validates offline:

```sh
liyasa schema config > liyasa.schema.json
```

If the key came from a newer release, upgrade rather than deleting it; if it
came from another tool, delete it.

[`E0102`](/errors/E0102) is the neighbouring case: the key exists and its value
has the wrong shape. [`E0121`](/errors/E0121) is a config written against a
newer schema version than this build knows.
