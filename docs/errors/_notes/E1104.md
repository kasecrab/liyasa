The source project's configuration did not parse. The message carries the
parser's line and column.

In practice this is `docs.json` or `mint.json` failing as JSON, and the cause is
almost always a trailing comma or a comment — both of which some editors accept
and JSON does not.

## Fix it

Correct the named position and import again. Nothing is planned when this fires,
so there is nothing to clean up.

The same code covers a much rarer case: the *converted* configuration failing to
serialize, which is a fault in Liyasa rather than anything in your project. Tell
them apart by what the message names. A source position is yours to fix; a
destination file is worth reporting.
