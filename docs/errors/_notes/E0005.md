`liyasa.lock` could not be read. Either it is not valid TOML, or its format
version is newer than this CLI understands.

The second case is the deliberate one. A lock written by a later Liyasa may
carry a key that changes what a build produces, and a build that ignored the key
would claim to reproduce something it did not.

## Fix it

If the file is corrupt, regenerate it:

```sh
liyasa lock update
```

If it was written by a newer Liyasa, upgrade rather than regenerate. Downgrading
the lock to match an older binary throws away whatever the newer one recorded.

The lock holds the Liyasa version, the theme preset, the bundled fonts by
digest, and the companion runtime. See [running the CLI](/help/cli).
