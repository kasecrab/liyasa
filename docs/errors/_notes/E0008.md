The artifact downloaded, and its SHA-256 digest is not the one the release index
names. The message carries both values.

## What to do

The update stops here, before the running binary is replaced. That is the design:
a failed update leaves you on the version you were already running.

A mismatched digest is usually a truncated or cached download — a proxy serving
a stale object is the common cause on a corporate network. Retry once from a
different network, and if it persists, download from the releases page and check
the digest by hand.

Do not disable the check. It and [`E0007`](/errors/E0007) are the only things
standing between `liyasa update` and running whatever arrived.
