Variant discovery did not settle within `build.variantDiscoveryIterations`.

A page that reads a dimension value is built once per combination, and
discovering which combinations exist is iterative: rendering a page can reveal
that it reads another dimension. Not converging means that process kept finding
more.

## Fix it

Nearly always a page whose template reads a dimension value computed from
another dimension value. Narrow what the page actually reads rather than raising
the iteration cap: the cap is protecting you from a combinatorial build.

[`W0710`](/errors/W0710) and [`E0711`](/errors/E0711) are the neighbouring
limits, per page and per site.
