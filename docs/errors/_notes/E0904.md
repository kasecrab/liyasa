A writing-agent run produced a change that the output gate refused, so no proposal was opened and nothing was written.

## Fix it

The message names each check that failed, and there are three kinds.

**A size cap.** `N files changed, and ai.agent.limits.maxFilesChanged is M` means the change is larger than the project allows in one go. Either narrow the task so the run touches fewer pages, or raise the key in `liyasa.json`. The same applies to `maxLinesChanged`, and to a page-delete cap that only lifts with an explicit flag.

**Something the run may not do.** A run triggered by feedback, a support ticket, a chat message or a pull request body may write only the pages its trigger named, and may not touch navigation, config, redirects, facts or `AGENTS.md`. There is nothing to configure here: the restriction comes from the trust level of the run's inputs and no key turns it off. Run the same task from a prompt if you meant to make that change yourself.

**Something no run should do.** A credential matching a secret pattern, front matter that no longer parses, or a link to a host the site does not already link to. Fix the content and run it again; a secret in a diff is a rejection at every trust level.

The gate does not consult the model, so its reasons cannot be argued with in a prompt.
