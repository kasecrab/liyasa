A block's language has a runner, and nothing says which image build of that
runner to use — `verify.runners.images` does not name it, `liyasa.lock` has no
row for it, or the reference it does have is a tag such as `rust:1.90` rather
than a digest.

## Fix it

Record the digest:

```
liyasa lock
```

or pin it by hand in `liyasa.json`:

```json
{ "verify": { "runners": { "images": {
  "rust": "docker.io/library/rust@sha256:<64 hex digits>"
} } } }
```

A tag moves. Two machines given the same `liyasa.lock` have to run the same
code against the same image, so an image the registry could re-point tomorrow
is refused rather than used and forgotten.

Related: [E0611](E0611.md) is the sandbox itself being unavailable;
[E0620](E0620.md) is the server refusing the `local` sandbox.
