A navigation file names another navigation file that Liyasa will not read: one
that is already part of this tree, or one more than four files deep. The subtree
keeps the path you wrote rather than the pages it names, so the build stops here
instead of publishing a tab with nothing in it.

Splitting a tree across files is `"pages": "nav/guides.json"` in place of the
array, and a file may name further files — up to four splices, counted from
`liyasa.json`. Two files that name each other have no end, so there is nothing
to read.

## Fix it

Find the file the message names and follow it back. The common cause is a file
that names the one that named it:

```json
// nav/guides.json
[{ "tab": "Guides", "pages": "nav/guides.json" }]   // itself
```

Point it at the pages instead, or flatten a level so the chain is shorter. If
four is genuinely not enough for your tree, say so rather than working around
it — the cap exists to turn an endless read into one diagnostic, not to ration
files.

See [W0130](/errors/W0130) for a page no navigation reaches, and
[E0104](/errors/E0104) for navigation naming a page that is not there.
