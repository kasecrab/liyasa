The importer scanned its own output and the converted page did not parse, so a
page that will not build is named during the migration rather than at the first
build afterwards.

The report carries the underlying code, which is what tells you which failure
you have.

| Code | What it is |
|---|---|
| [`E0301`](/errors/E0301) | An unclosed code fence. By far the most common |
| [`E0101`](/errors/E0101), [`E0102`](/errors/E0102) | Front matter that is not valid YAML, or does not match the schema |
| [`E0310`](/errors/E0310) | A container directive opened and never closed |
| [`E0212`](/errors/E0212) | A private-use Unicode character, which Liyasa reserves for expansion sentinels |

## Fix it

Open the converted page at the named position and correct it. Then check the
same place in the source, because the defect is usually there too — an unclosed
fence renders one way under a lenient pipeline and another under a strict
scanner, so it can sit in published documentation for years unnoticed.

The page is still written out unchanged. The content is safe; it will not build
until the markup is fixed.
