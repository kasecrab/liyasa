# E0852

**AI credits are spent and overage is turned off**

| | |
|---|---|
| Severity | Error |
| Area | Server, auth, deployments, network |
| Raised by | `liyasa-server` |

An assistant answer or an agent task was priced in credits, the balance will
not cover it, and this organization has the overage setting turned off — so
the work was refused rather than run and billed.

## Fix it

Buy a top-up, which is spendable immediately and does not roll over:

```
liyasa org credits top-up 500
```

Or allow overage, which runs the work and bills the credits past the pool:

```
liyasa org credits --overage on
```

Or bring your own key, which bypasses credits entirely — the provider bills you
directly and nothing here is metered. Sandbox minutes are still metered under
a key of your own: those are our machines whoever paid for the model.

An agent task's price comes from its size, and a run that turns out larger than
it was quoted is reconciled against the published token estimate rather than
silently costing more.

Related: [E0850](E0850.md) for the other metered resources, which run out on
their own schedule.
