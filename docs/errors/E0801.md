# E0801

**Domain verification failed**

| | |
|---|---|
| Severity | Error |
| Area | Server, auth, deployments, network |
| Raised by | `liyasa-server` |

The custom domain did not prove it belongs to you and points here, so it was
not verified.

Verification checks two records, and the message says which one failed. The TXT
record at `_liyasa-challenge.<your-domain>` proves you control the zone. Then
the pointing record proves the name reaches this deployment: a CNAME for a
subdomain, or, at an apex where CNAME is not allowed, an ALIAS or the address
records your provider documents.

## Fix it

Both records have to exist before verification passes, and DNS changes are not
instant — a provider that caches for an hour means waiting an hour, however
quickly the record appeared in their dashboard.

The TXT value is issued when you add the domain and is specific to it. Copy it
exactly, including the `liyasa-site-verification=` prefix: a value without the
prefix is ignored, so that an unrelated TXT record on the same name cannot be
mistaken for a challenge.

"Has not been claimed by any project" means the domain was never added, or the
claim expired. Add it again for a fresh challenge value.

A domain another organization already owns is refused unless you claim it as a
contest, which is settled by the same TXT proof and notifies the current owner.

See [`E0802`](/errors/E0802) for certificate issuance, which runs after a domain
is verified, and [`E0803`](/errors/E0803) for an auth provider that is
misconfigured.
