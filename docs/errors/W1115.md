# W1115

**Page route changed; a redirect from the old URL was generated**

| | |
|---|---|
| Severity | Warning |
| Area | Importers |
| Raised by | `liyasa-import` |

A page's route changed during conversion, and a redirect from the old URL was
added to `redirects` in the converted `liyasa.json`.

Most migrations produce none of these: the importer writes each page where its
original URL says it should go. It fires where the two products genuinely
disagree, such as a Docusaurus archived version at `/docs/1.0/intro`, which
becomes `/1.0/docs/intro` because Liyasa serves a version under the version
rather than under the route base.

## Fix it

:::warning{title="The generated rule is half the job"}
A rule in the new site's configuration only redirects readers who already reach
the new site. Anyone holding an old URL is still being served by whatever hosts
the old documentation, so the redirect has to exist there too, or the old host
has to point at the new one.
:::

Nothing needs changing inside the converted project. What needs doing is on the
host you are migrating away from. See [linking](/guides/linking) for how
redirects are written and [hosting](/guides/hosting) for what each host does
with them.
