# W0726

**A `:::variation` directive names a variation or option `variations` does not declare**

| | |
|---|---|
| Severity | Warning |
| Area | Build, cache, assets, determinism |
| Raised by | `liyasa-build` |

A `:::variation{name="option"}` directive used a variation name that
`variations` does not list, or an option outside the `options` that variation
declares. The block still renders — a variation is a switcher, not a gate — but
it belongs to no switcher, so a reader has no way to reach it.

## Fix it

Declare the variation and its options:

```json
{
  "variations": [
    { "name": "deployment", "label": "Deployment",
      "options": ["cloud", "self-hosted"] }
  ]
}
```

or correct the directive to one that is declared:

```md
:::variation{deployment="self-hosted"}
Run the container behind your own proxy.
:::
```

A variation that declares no `options` learns them from the directives
themselves, so only the variation name is checked in that case and no option is
ever reported against it.

A variation is never a security boundary: every option's text is in the
delivered HTML and the switcher only chooses which one is shown. For content a
reader must not receive, use [`W0725`](W0725)'s regions or an access group —
those withhold the bytes.

Related: [`W0725`](W0725) for an undeclared region.
