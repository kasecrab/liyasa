# E1105

**JavaScript configuration is not a literal object; run the generated Node script and import its JSON**

| | |
|---|---|
| Severity | Error |
| Area | Importers |
| Raised by | `liyasa-import` |

`docusaurus.config.js` and `sidebars.js` are modules rather than data. The
importer evaluates them in an embedded JavaScript engine, which handles a
literal object written as `module.exports = {…}` or `export default {…}`. This
one reaches outside itself.

The usual cause by a wide margin is a theme import:

```js
const {themes} = require('prism-react-renderer');
// ... themeConfig.prism.theme = themes.github
```

A TypeScript config with type annotations fails the same way, as does one
reading `process.env`.

## Fix it

The importer does not guess. It writes a one-line Node script into the converted
project and tells you to run it:

```sh
node liyasa-export-config.mjs ./docusaurus.config.js
```

That imports the module the way Node does and writes the JSON beside the source,
so `docusaurus.config.js` becomes `docusaurus.config.json`. Import again and the
JSON is picked up in preference to the module. It handles CommonJS and ESM
alike.

The script is written into the **destination**, next to the converted project.
The argument is the path to the source module.
