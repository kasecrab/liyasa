# E0010

**`--locked` refused a change to `liyasa.lock`**

| | |
|---|---|
| Severity | Error |
| Area | CLI and I/O |
| Raised by | `liyasa-cli` |

`--locked` was given, and the build would have changed `liyasa.lock`. The
message names what would have changed.

This is the point of the flag. In CI, a build that quietly rewrites the lock is
a build that is not reproducing anything, and the difference between "the lock
was already right" and "the lock has been made right" is the whole value of
having one.

## Fix it

Run the update locally, read the diff, and commit it:

```sh
liyasa lock update
git diff liyasa.lock
```

If the change is unexpected — a font digest moving, a theme preset switching
source — that is a finding, not a formality. Dropping `--locked` to make CI pass
converts a caught change into an uncaught one.
